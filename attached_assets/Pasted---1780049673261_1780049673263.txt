Клиентская часть веб-приложения отвечает за весь пользовательский интерфейс и формирует основной канал взаимодействия покупателя с системой. На уровне клиента реализованы все пользовательские сценарии: просмотр каталога, поиск и фильтрация товаров, пошаговый направленный подбор по заданным характеристикам, ведение корзины, оформление заказа, регистрация и авторизация, личный кабинет, программа лояльности и административная панель. В качестве технологической основы используются React, TypeScript и Vite, выбор которых обоснован в подразделе 2.3, в сочетании с дополнительными библиотеками, образующими целостную и согласованную клиентскую экосистему.
Клиентское приложение размещается в директории client/ исходного дерева проекта. Структура каталога соответствует принципам организации современных React-приложений: точка входа и конфигурация сборки находятся в корне директории, исходный код пользовательского интерфейса — в поддиректории src/, статические ресурсы — в public/. Внутри src/ исходный код разделён на тематические поддиректории: components/ содержит переиспользуемые компоненты интерфейса, pages/ — компоненты страниц приложения, hooks/ — пользовательские хуки, lib/ — служебные модули и конфигурации внешних библиотек. Подобная организация облегчает навигацию по проекту и обеспечивает чёткое разделение ответственности между частями клиентской логики.
В качестве сборщика используется Vite, обеспечивающий высокую скорость разработки и удобство работы с TypeScript. На стадии разработки Vite применяет горячую замену модулей, что позволяет видеть изменения в интерфейсе мгновенно. При сборке для эксплуатации Vite формирует оптимизированный комплект статических файлов с разделением на чанки, что положительно сказывается на времени первой загрузки страницы. Конфигурация сборщика описана в файле vite.config.ts и поддерживает алиасы путей, что повышает удобство импорта модулей из удалённых частей дерева исходного кода.
Маршрутизация клиентского приложения реализована с помощью библиотеки Wouter, представляющей собой минималистичный маршрутизатор для React. Wouter был выбран как лёгковесная альтернатива более тяжёлым решениям типа React Router: он обеспечивает необходимый набор возможностей для приложения интернет-магазина — определение маршрутов, передачу параметров, программную навигацию и условный рендеринг — без избыточных абстракций. Дерево маршрутов организовано вокруг ключевых разделов: главная страница, каталог товаров, карточка товара, страница пошагового подбора, корзина, оформление заказа, личный кабинет пользователя, административная панель. Для административной части реализован защищённый маршрутный сегмент, доступ к которому контролируется отдельно: при попытке открытия его страниц неавторизованным пользователем клиент перенаправляется на страницу входа.
Управление серверным состоянием выполняется с помощью библиотеки TanStack Query. Применение специализированного инструмента работы с серверными данными позволяет отделить серверное состояние от клиентского и реализовать единый паттерн обращения к API: кеширование ответов, автоматическое перезапрашивание при изменении зависимостей, инвалидация кеша при мутациях, отслеживание состояния загрузки и ошибок, фоновое обновление данных. Подобный подход существенно упрощает реализацию страниц, обращающихся к серверу, и сокращает объём шаблонного кода. Локальное состояние интерфейса, не требующее синхронизации с сервером, обрабатывается стандартными средствами React (useState, useReducer) либо контекстом.
Пользовательский интерфейс построен на базе библиотеки компонентов shadcn/ui, основанной на примитивах Radix UI, и системе утилитарных стилей Tailwind CSS. Подобное сочетание обеспечивает с одной стороны доступность и стандартизованное поведение интерактивных компонентов (диалоги, выпадающие меню, выпадающие списки, переключатели, формы), а с другой — гибкость визуального оформления через применение утилитарных классов Tailwind. Все ключевые элементы интерфейса — кнопки, поля ввода, карточки товаров, диалоговые окна, элементы навигации, модальные окна — реализованы как переиспользуемые компоненты в директории components/, что соответствует принципам компонентной декомпозиции, рассмотренным в подразделе 2.3.
Работа с формами организована средствами библиотеки React Hook Form, отвечающей за управление состоянием полей, отслеживание изменений и обработку отправки. Валидация полей выполняется через интеграцию с Zod: для каждой формы определена соответствующая Zod-схема, расположенная в директории shared/. Такая организация позволяет переиспользовать одну и ту же схему как для валидации на клиенте до отправки запроса, так и для валидации на сервере при получении данных, что обеспечивает согласованность ограничений между обеими частями системы. Сообщения об ошибках валидации формируются на основании схемы и отображаются непосредственно у соответствующих полей, что соответствует принципам юзабилити и упрощает исправление ввода.
Главная страница и страница каталога реализуют просмотр ассортимента с поддержкой различных способов взаимодействия. На главной странице отображается подборка популярных или выделенных товаров. Страница каталога обеспечивает основную часть пользовательских сценариев выбора: пользователь может последовательно сужать выборку по категории, набору тегов и диапазону цен, выполнять поиск по наименованию, изменять порядок сортировки и переходить к карточкам отдельных товаров. Каталог реализован с поддержкой пагинации и подгрузки по запросу, что обеспечивает плавную работу при значительном числе товарных позиций. Запросы к серверу выполняются через TanStack Query с использованием параметров в качестве ключа кеша, что обеспечивает быстрое возвращение к ранее просмотренным комбинациям фильтров.
Карточка отдельного товара отображает подробное описание, характеристики и галерею изображений с возможностью увеличения. На странице карточки предусмотрены управляющие элементы добавления товара в корзину, выбор количества и переход к связанным позициям. Если товар отсутствует на складе, соответствующая визуальная индикация информирует пользователя и блокирует возможность добавления в корзину.
Страница пошагового направленного подбора реализует один из центральных функциональных сценариев приложения. Пользователь последовательно отвечает на серию вопросов, формулировки и варианты ответов которых задаются администратором. По завершении сценария клиент отправляет на сервер выбранные ответы и получает ранжированную выборку товаров, наиболее соответствующих заданным предпочтениям. Реализация подбора учитывает требования юзабилити: количество шагов остаётся обозримым, у пользователя есть возможность вернуться к предыдущему вопросу, а итоговая страница сопровождается понятным объяснением, на основании каких параметров сформирована рекомендация. После просмотра итоговой подборки пользователь может перейти к карточке выбранного товара или продолжить уточнение средствами обычных фильтров каталога. Подобный сценарий реализует требование интеграции направленного подбора с основным каталогом, сформулированное в разделе 3.1.
Корзина и оформление заказа реализованы как отдельный пользовательский поток. Состояние корзины синхронизируется с серверным хранилищем для аутентифицированных пользователей и хранится в локальном клиентском состоянии для гостей. Страница корзины отображает выбранные товары, итоговую сумму и применимые скидки. На странице оформления заказа пользователь выбирает адрес доставки из ранее сохранённых или вводит новый, подтверждает состав заказа и инициирует его создание. Все этапы оформления сопровождаются валидацией ввода и обработкой ошибок, возвращаемых сервером.
Личный кабинет включает несколько разделов. На странице профиля пользователь редактирует контактные данные, проходит подтверждение телефона и управляет признаком получения уведомлений. Раздел сохранённых адресов позволяет добавлять, редактировать и удалять адреса доставки. Раздел истории заказов отображает все ранее оформленные заказы с возможностью просмотра их статуса и состава. Раздел программы лояльности показывает текущий баланс баллов, накопительный уровень, применимую скидку и историю операций с баллами, формируемую на основании таблицы xp_transactions. Подобная организация обеспечивает прозрачность программы лояльности и формирует доверие пользователей к системе начислений.
Административная панель реализована как отдельный раздел приложения с собственной навигацией. Внутри панели предусмотрены страницы управления товарами, категориями, тегами, заказами, пользователями и общими настройками сайта. Для каждой сущности реализован унифицированный набор операций: просмотр списка с фильтрацией и поиском, добавление новой записи, редактирование, удаление с подтверждением.  Все операции административной панели обращаются к защищённым серверным маршрутам и сопровождаются соответствующей обратной связью при возникновении ошибок.
Адаптивность интерфейса обеспечивается совместным применением утилитарных классов Tailwind CSS и компонентов из shadcn/ui. Все ключевые страницы разработаны с учётом mobile-first подхода: базовая компоновка ориентирована на узкий экран мобильного устройства, а при увеличении ширины контейнера применяются дополнительные правила, перестраивающие сетку и расположение элементов. Размеры интерактивных областей (кнопок, ссылок, элементов навигации) удовлетворяют требованиям мобильных интерфейсов, шрифты сохраняют читаемость на малых экранах, а навигация в мобильной версии реализована с использованием паттернов, привычных пользователю смартфона.
Поддержка Progressive Web Application организована средствами манифеста приложения и сервисного работника. Манифест содержит сведения о наименовании, иконках, цветовой схеме и режиме отображения, что позволяет пользователю установить приложение на устройство и запускать его в полноэкранном режиме без интерфейса браузера. Сервисный работник реализует базовое кеширование статических ресурсов и обеспечивает работоспособность приложения при ограниченной доступности сети для уже посещённых страниц.
Для распространения приложения как мобильного приложения для Android используется Capacitor. Capacitor оборачивает web-приложение в нативный контейнер, обеспечивая запуск в среде Android при сохранении единой кодовой базы. Сборка APK-файла настроена в составе репозитория и может выполняться автоматически средствами GitHub Actions, что обеспечивает воспроизводимость сборки и упрощает выпуск обновлений. Применение Capacitor не требует переписывания клиентского кода и позволяет дополнительно интегрировать нативные возможности устройства через систему плагинов, что предоставляет потенциал для дальнейшего развития мобильной части системы.
Таким образом, клиентская часть разработанного приложения реализует полный пользовательский интерфейс, обеспечивает работу всех функциональных сценариев системы и сохраняет согласованность с серверной частью благодаря общей модели данных и единым Zod-схемам. Сочетание React, TypeScript, Vite, Wouter, TanStack Query, shadcn/ui и Tailwind CSS обеспечивает структурированность, гибкость, удобство сопровождения и адаптивность интерфейса. Применение Capacitor для упаковки в Android-приложение и средств PWA для расширения web-сценария обеспечивает кроссплатформенность системы при сохранении единой кодовой базы. Совокупность реализованных решений соответствует функциональным и нефункциональным требованиям, сформулированным в начале настоящей главы, и подтверждает целесообразность принятых архитектурных и технологических выборов.
