# Склад и офлайн-продажи

- `/admin?tab=warehouse`: чай, посуда, история операций. Цена чая за грамм, посуды за штуку. Единица берётся из `products.pricing_unit` (штучный чай остаётся штучным).
- `/admin?tab=users`: существующая страница XP с продажей. Единственный сотрудник выбирается автоматически. Без выбранного клиента продажа оформляется как анонимная; для начисления XP выберите клиента через поиск. Если нужного чая ещё нет, выберите «Новый чай», введите название, цену за грамм и проданную граммовку. Чай создаётся при подтверждении продажи, отдельное добавление не требуется. Сумма и XP считаются автоматически с текущим `settings.xp_multiplier`. Анонимная продажа не создаёт клиента и не начисляет XP.
- Отмена в последних продажах возвращает товар и снимает начисленные XP в пределах текущего баланса; повторная отмена безопасна.

## Первый запуск

При запуске сервера создаются `inventory_stock`, `inventory_sales`, `inventory_movements` (идемпотентный DDL в `server/inventory.ts`). Подключение `DATABASE_URL` должно иметь права изменения схемы. До первого пересчёта остаток существующего чая неизвестен, а посуды равен нулю. Фактические остатки вносятся при инвентаризации; из старых заказов они не рассчитываются.

Цены используются из существующего каталога. Изменение цены на складе меняет цену товара и на сайте. Полноценные карточки с фото создаются в существующей вкладке «Товары».

Чай, добавленный непосредственно в продаже, появляется в общей таблице товаров и на складе как внутренняя позиция (`inventory_only=true`, `out_of_stock=true`). Его исходный остаток неизвестен (`NULL`), продажи и отмены не превращают это неизвестное значение в отрицательное или положительное количество. При первой фактической инвентаризации администратор устанавливает остаток в «Склад → Чай»; последующие продажи уже уменьшают его. Внутренняя позиция скрыта с витрины, из фида и из каталога Telegram-бота. После оформления фото и описания её можно опубликовать в карточке товара, сняв флаг «Только в CRM» и при необходимости «Товар закончился».

Это учёт офлайн-продаж через новый экран. Интернет-заказы, наборы и ручное начисление XP сами по себе склад не списывают. Новая продажа отражается в истории склада и XP, но не создаёт оплаченный интернет-заказ и не является фискальным чеком.

## Защита данных

Создание нового чая, сохранение продажи, движений и XP проходит в одной транзакции. Остатки блокируются на время изменения; коррекция требует совпадения revision. Повтор продажи с тем же requestId возвращает сохранённый результат, с другим содержимым отклоняется. История хранит снимки названия, цены, количества, клиента и сотрудника.

## Проверка

`npm run test:inventory` использует отдельную PGlite в памяти, без доступа к рабочей БД. Проверяет продажу клиенту/анониму, повтор, нехватку товара, устаревшую цену/остаток, полный rollback при сбое XP и повторную отмену. PostgreSQL-конкурентность этим однопоточным тестом не проверяется. Дополнительно: `npm run check`, `npm run build`.
